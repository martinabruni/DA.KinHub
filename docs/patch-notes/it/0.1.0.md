# KinHub 0.1.0 — Note di rilascio

- **added / developer-experience**: Aggiunta una skill per trasformare analisi funzionale e architettura in feature autonome, tracciabili e ordinate per dipendenze e parallelismi sicuri.
- **added / platform**: Aggiunta la base full-stack di KinHub con API, PWA bilingue, temi, tutorial, guida contestuale, skill, infrastruttura Azure e pipeline.
- **changed / docs**: Consolidate nella ricerca KinList le decisioni su paginazione repository, limiti batch, timer giornaliero, identità, inviti, pipeline vocale e comportamento PWA.
- **added / docs**: Aggiunto il backlog esecutivo KinList con 13 feature autonome, tracciabilità completa, dipendenze, wave, gate e criteri verificabili.
- **changed / architecture**: Documentata la pipeline HTTP Functions centralizzata e sicura per default, con Change Request FEAT-001, regole OpenTelemetry, convenzioni CR e reference skill validate dall'harness.
- **changed / backend**: Implementata la pipeline HTTP condivisa della Function App con correlation ID, Problem Details centralizzati, autorizzazione default-deny, route/OpenAPI condivise e telemetria worker basata su Azure Monitor OpenTelemetry.
- **changed / backend**: KinList ora crea o riusa un profilo applicativo da `(iss, oid)`, verifica la membership familiare attiva nel bootstrap post-login, espone la policy `Family` e mantiene offline soltanto la shell pubblica senza dati personali.
- **changed / backend**: FEAT-001 ora completa il percorso finale di accesso KinList con contesto famiglia solo in memoria, test frontend mirati, guardrail repository-wide per route/OpenAPI Functions e deploy Azure PostgreSQL basato su Microsoft Entra e token identity-based per principal e migration.
- **fixed / backend**: KinList ora usa un upsert atomico per il profilo applicativo `(iss, oid)`, tratta come indisponibilita del repository solo i guasti reali di persistenza e richiede una configurazione database esplicita tra `ConnectionString` locale e `ManagedIdentity`.
