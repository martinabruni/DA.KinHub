# KinHub 0.1.0 — Note di rilascio

- **added / developer-experience**: Aggiunta una skill per trasformare analisi funzionale e architettura in feature autonome, tracciabili e ordinate per dipendenze e parallelismi sicuri.
- **added / platform**: Aggiunta la base full-stack di KinHub con API, PWA bilingue, temi, tutorial, guida contestuale, skill, infrastruttura Azure e pipeline.
- **changed / docs**: Consolidate nella ricerca KinHub e KinList le decisioni condivise su identita e inviti e quelle specifiche del servizio su paginazione, limiti batch, timer giornaliero, pipeline vocale e comportamento PWA.
- **added / docs**: Aggiunto il backlog esecutivo KinList con 13 feature autonome, tracciabilità completa, dipendenze, wave, gate e criteri verificabili.
- **changed / tooling**: Aggiornato l'harness con esecuzione autonoma delle feature fino alla Definition of Done, checkpoint riprendibili solo per soglia del contesto o human in the loop e consegna tramite pull request senza merge.
- **changed / architecture**: Documentata la pipeline HTTP Functions centralizzata e sicura per default, con Change Request FEAT-001, regole OpenTelemetry, convenzioni CR e reference skill validate dall'harness.
- **changed / backend**: Implementata la pipeline HTTP condivisa della Function App con correlation ID, Problem Details centralizzati, autorizzazione default-deny, route/OpenAPI condivise e telemetria worker basata su Azure Monitor OpenTelemetry.
- **changed / backend**: KinHub ora crea o riusa un profilo applicativo da `(iss, oid)`, verifica la membership familiare attiva nel bootstrap post-login, espone la policy `Family` condivisa e mantiene offline soltanto la shell pubblica senza dati personali.
- **changed / backend**: FEAT-001 ora completa il percorso di accesso KinHub consumato da KinList, con contesto famiglia condiviso solo in memoria, test frontend mirati, guardrail repository-wide per route/OpenAPI Functions e deploy Azure PostgreSQL basato su Microsoft Entra e token identity-based per principal e migration.
- **fixed / backend**: KinHub ora usa un upsert atomico per il profilo applicativo `(iss, oid)`, tratta come indisponibilita del repository solo i guasti reali di persistenza e richiede una configurazione database esplicita tra `ConnectionString` locale e `ManagedIdentity`.
- **fixed / backend** ⚠️: Bootstrap, contesto famiglia, autorizzazione e telemetria condivisi usano ora nomenclatura e route KinHub; rimossi i contratti `/api/kinlist/bootstrap` e `/api/kinlist/family-context` attribuiti erroneamente al KinService.
