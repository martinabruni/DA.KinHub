# KinHub 0.1.0 — Release notes

- **added / developer-experience**: Added a skill that turns functional analysis and architecture into autonomous, traceable features ordered by dependencies and safe parallel work.
- **added / platform**: Added the KinHub full-stack foundation with API, bilingual PWA, themes, tutorial, contextual help, skills, Azure infrastructure, and pipelines.
- **changed / docs**: Consolidated KinList research decisions for repository pagination, batch limits, the daily timer, identity, invitations, the voice pipeline, and PWA behavior.
- **added / docs**: Added the KinList execution backlog with 13 autonomous features, complete traceability, dependencies, waves, gates, and verifiable acceptance criteria.
- **changed / architecture**: Documented the centralized, secure-by-default Functions HTTP pipeline, including the FEAT-001 change request, OpenTelemetry rules, CR conventions, and skill references validated by the harness.
- **changed / backend**: Implemented the shared Function App HTTP pipeline with correlation ID, centralized Problem Details, default-deny authorization, shared routes/OpenAPI, and Azure Monitor OpenTelemetry-based worker telemetry.
- **changed / backend**: KinList now creates or reuses an application profile from `(iss, oid)`, verifies the active family membership during the post-login bootstrap, exposes the `Family` policy, and keeps only the public shell available offline without personal data.
- **changed / backend**: FEAT-001 now completes the final KinList access-routing path with in-memory family context, targeted frontend tests, repository-wide Functions route/OpenAPI guardrails, and Azure PostgreSQL deployment based on Microsoft Entra plus identity-based tokens for principals and migrations.
- **fixed / backend**: KinList now uses an atomic upsert for the `(iss, oid)` application profile, treats only real persistence failures as repository unavailability, and requires an explicit database configuration between local `ConnectionString` and `ManagedIdentity`.
