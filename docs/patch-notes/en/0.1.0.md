# KinHub 0.1.0 — Release notes

- **added / developer-experience**: Added a skill that turns functional analysis and architecture into autonomous, traceable features ordered by dependencies and safe parallel work.
- **added / platform**: Added the KinHub full-stack foundation with API, bilingual PWA, themes, tutorial, contextual help, skills, Azure infrastructure, and pipelines.
- **changed / docs**: Consolidated shared KinHub decisions for identity and invitations and KinList-specific decisions for repository pagination, batch limits, the daily timer, the voice pipeline, and PWA behavior.
- **added / shared**: KinHub can now create the first family from `/kinlist` with a single name, atomic family plus creator membership persistence, a dedicated endpoint, and updated onboarding.
- **added / backend**: Added the persisted family service catalog with KinList preconfigured, availability assigned to existing and new families, a dynamic Home driven by authorized services, and a server-side access check for direct `/kinlist` navigation.
- **added / frontend**: Added the `/settings/family` route with family name reading, active member and active invitation pages, new protected KinHub Family endpoints, and linked bilingual documentation.
- **added / frontend**: KinHub adds the first paginated shared KinList view with a minimal persisted backend, opaque cursors, stable ordering, essential categories, author details, and previous/next navigation without local data caching.
- **added / docs**: Added the KinList execution backlog with 13 autonomous features, complete traceability, dependencies, waves, gates, and verifiable acceptance criteria.
- **changed / tooling**: Updated the harness with autonomous feature execution through the Definition of Done, resumable checkpoints only for the context threshold or human-in-the-loop needs, and pull request delivery without merging. Every pull request GitHub Action must be green on the latest commit; each red run requires diagnosis, a fix, and another push.
- **changed / documentation**: Added progress frontmatter to backlog feature documents, with an explicit state machine and completion reserved for a direct command from the human owner.
- **changed / architecture**: Documented the centralized, secure-by-default Functions HTTP pipeline, including the FEAT-001 change request, OpenTelemetry rules, CR conventions, and skill references validated by the harness.
- **changed / backend**: Implemented the shared Function App HTTP pipeline with correlation ID, centralized Problem Details, default-deny authorization, shared routes/OpenAPI, and Azure Monitor OpenTelemetry-based worker telemetry.
- **changed / frontend**: Move contextual help out of the pages, update the user guide, and add a direct entry-point link to the getting-started guide in the Information menu.
- **changed / tooling**: Strengthened the implementation harness and bootstrap prompt with anti-regression guardrails derived from the repository's real fixes: verified Azure versions/runtimes, repository-wide configuration renames, workflow contracts, Flex Consumption, identity-based storage, migration bundles, generated artifacts, and post-deploy live checks.
- **changed / tools**: Extended the implementation harness to all versioned repository changes, including fixes, workflows, and documentation, making commit, push, pull request, and GitHub Actions monitoring mandatory even outside backlog features.
- **changed / tools**: Made the implementation harness explicit that moving a feature to `In review` always requires commit and push on `dev`, an open pull request to `main`, and green GitHub Actions on the latest SHA before delivery can be considered complete.
- **changed / backend**: KinHub now creates or reuses an application profile from `(iss, oid)`, verifies active family membership during post-login bootstrap, exposes the shared `Family` policy, and keeps only the public shell available offline without personal data.
- **changed / backend**: FEAT-001 now completes the KinHub access-routing path consumed by KinList, with shared in-memory family context, targeted frontend tests, repository-wide Functions route/OpenAPI guardrails, and Azure PostgreSQL deployment based on Microsoft Entra plus identity-based tokens for principals and migrations.
- **changed / frontend**: The MSAL cache uses `sessionStorage` to preserve the tab session across refreshes. The family bootstrap remains mandatory, and application data continues to live only in memory.
- **changed / tooling**: The harness now verifies that every HTTP Function route is documented in `openapi.yaml`, requiring the static contract to be updated with every new endpoint.
- **changed / infra**: Merges to `main` now automatically deploy only the changed scope: application code uses the lightweight deployment, while infrastructure and migrations use a serialized full-stack path that updates the database before the code without duplicate deployments.
- **changed / infra**: Separated Azure deployments by responsibility: `infra/**` only provisions Bicep resources, `src/backend/**` applies migrations and deploys the Function App, and `src/frontend/**` only deploys the SPA, while preserving the correct order for mixed commits.
- **changed / frontend**: I integrate the shared design system into the shell and current routes, remove the demo route, add a validator, and promote the official primitives, floating navigation, and frontend patterns in documentation.
- **fixed / infra**: Fixed the deployment workflows to use fallbacks compatible with the secrets and variables already present in the `dev` environment, and to derive the OIDC principal object id from the ARM token instead of a fragile Graph lookup.
- **fixed / infra**: Fixed `deploy-infrastructure.yml` to resolve the PostgreSQL Entra administrator name and object id reliably, preventing empty parameters that invalidated the Bicep deployment.
- **fixed / infra**: Fixed the EF Core bundle step in the deployment workflows by using the Infrastructure design-time factory instead of forcing the Function App as the startup project.
- **fixed / infra**: Fixed the `dotnet ef migrations bundle` command in the deployment workflows by removing the invalid `--self-contained false` argument, which was breaking EF Core bundle generation.
- **fixed / security**: Microsoft Entra External ID configuration now separates the customer tenant from the Azure tenant and correctly validates the CIAM authority, GUID audience, and API token scope name.
- **fixed / shared**: Aligned KinList onboarding copy with the already-available family creation flow and added real PostgreSQL coverage for FEAT-002 migrations, repository retry, and concurrency.
- **fixed / infra**: Fixed the Bicep resources for dev deployments by removing the `FUNCTIONS_WORKER_RUNTIME` app setting, which is invalid for Azure Functions Flex Consumption, and aligning the Key Vault parameter with purge protection already enabled.
- **fixed / infrastructure**: Corrected the Flex Function App .NET 10 runtime so workers can be allocated, preventing 503 responses without telemetry.
- **fixed / backend**: Fixed the Function App authorization middleware to resolve scoped services per invocation instead of from the singleton constructor, with a regression test that validates DI container startup when the middleware is registered.
- **fixed / backend**: Fixed the Function App OpenTelemetry registration to avoid initializing the Azure Monitor exporter when `APPLICATIONINSIGHTS_CONNECTION_STRING` is not configured, preventing local host startup crashes and covering the case with a regression test.
- **fixed / backend**: Aligned the Azure Functions Worker and gRPC libraries with the version required by the OpenTelemetry integration, removed an unsupported runtime setting, made the managed-identity host storage configuration unambiguous on Flex Consumption, and neutralized application placeholders that caused bootstrap crashes when environment overrides were missing.
- **fixed / backend**: KinHub now uses an atomic upsert for the `(iss, oid)` application profile, treats only real persistence failures as repository unavailability, and requires an explicit database configuration between local `ConnectionString` and `ManagedIdentity`.
- **fixed / backend** ⚠️: Shared bootstrap, family context, authorization, and telemetry now use KinHub naming and routes; the incorrectly KinService-scoped `/api/kinlist/bootstrap` and `/api/kinlist/family-context` contracts were removed.
- **fixed / infra**: Fixed the deployment workflows to use the correct Azure CLI arguments when managing the PostgreSQL Flexible Server firewall rule, separating `--server-name` from the firewall rule name.
- **fixed / infra**: Fixed temporary PostgreSQL firewall rule provisioning in the deployment workflows by replacing `az postgres flexible-server firewall-rule` with ARM calls through `az rest`, and made code deployments reliable by dynamically resolving the Function App, server, host, and database directly from Azure resources instead of depending on app settings or static names.
- **fixed / frontend**: Make the release notes page responsive on mobile and remove the duplicated card surface, keeping one card per entry.
- **fixed / backend**: Fixed the telemetry test that could intermittently fail while integration tests ran in parallel.
