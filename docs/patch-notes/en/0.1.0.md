# KinHub 0.1.0 — Release notes

- **added / developer-experience**: Added a skill that turns functional analysis and architecture into autonomous, traceable features ordered by dependencies and safe parallel work.
- **added / platform**: Added the KinHub full-stack foundation with API, bilingual PWA, themes, tutorial, contextual help, skills, Azure infrastructure, and pipelines.
- **changed / docs**: Consolidated shared KinHub decisions for identity and invitations and KinList-specific decisions for repository pagination, batch limits, the daily timer, the voice pipeline, and PWA behavior.
- **added / docs**: Added the KinList execution backlog with 13 autonomous features, complete traceability, dependencies, waves, gates, and verifiable acceptance criteria.
- **changed / tooling**: Updated the harness with autonomous feature execution through the Definition of Done, resumable checkpoints only for the context threshold or human-in-the-loop needs, and pull request delivery without merging.
- **changed / architecture**: Documented the centralized, secure-by-default Functions HTTP pipeline, including the FEAT-001 change request, OpenTelemetry rules, CR conventions, and skill references validated by the harness.
- **changed / backend**: Implemented the shared Function App HTTP pipeline with correlation ID, centralized Problem Details, default-deny authorization, shared routes/OpenAPI, and Azure Monitor OpenTelemetry-based worker telemetry.
- **changed / backend**: KinHub now creates or reuses an application profile from `(iss, oid)`, verifies active family membership during post-login bootstrap, exposes the shared `Family` policy, and keeps only the public shell available offline without personal data.
- **changed / backend**: FEAT-001 now completes the KinHub access-routing path consumed by KinList, with shared in-memory family context, targeted frontend tests, repository-wide Functions route/OpenAPI guardrails, and Azure PostgreSQL deployment based on Microsoft Entra plus identity-based tokens for principals and migrations.
- **fixed / backend**: KinHub now uses an atomic upsert for the `(iss, oid)` application profile, treats only real persistence failures as repository unavailability, and requires an explicit database configuration between local `ConnectionString` and `ManagedIdentity`.
- **fixed / backend** ⚠️: Shared bootstrap, family context, authorization, and telemetry now use KinHub naming and routes; the incorrectly KinService-scoped `/api/kinlist/bootstrap` and `/api/kinlist/family-context` contracts were removed.
